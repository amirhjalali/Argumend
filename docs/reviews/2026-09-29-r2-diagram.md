## What changed

**One model, from the page's model.** `lib/diagram/model.ts` builds the diagram from `legacyTopicPage(topic)` (`lib/topicPage/legacy.ts`), the same model the topic page renders. The diagram and the page therefore can't drift. The tree is:

- **Root:** the page's H1 (`topic.question ?? title`).
- **One branch per crux,** labelled with `crux.question` and using the page's fallback. The pillar title is the kicker, as on the crux sheet, and branches are numbered as the page numbers them.
- **Supporters and Skeptics under each crux.** These are the page's position-card labels. The box shows the first sentence of that pillar's case. The detail sheet shows the full case, which is what the page's "Read the full case" fold shows.
- **Evidence under the side it supports,** labelled by the card title. There is no badge: the page shows no strength word, so the diagram shows none either.

No string is written for the diagram. The model's test asserts there are no placeholders, no image fields and no score, weight or balance fields.

**Layout computed up front.** `lib/diagram/layout.ts` gives each kind of box a fixed size, with its text clamped to fit. There is one column per crux. The two sides sit side by side under each crux, and evidence stacks under its side off a spine. Nothing moves after render. `lib/diagram/layout.test.ts` builds all 156 maps and asserts:
- no two boxes come within 8px of each other;
- every child sits below its parent;
- every box is inside the tree's bounds;
- the whole tree fits a 1440×679 canvas at 45% zoom or more.

**Canvas** (`components/DesktopCanvas.tsx`, `components/nodes/DiagramNode.tsx`):
- **No expanding.** The whole tree is drawn, and `fitView` frames all of it on load. The fit control reuses the same `FIT_VIEW` settings.
- **The route fills the screen.** On desktop the route is exactly one screen: header, a compact intro, and the canvas filling the rest.
- **Colours.** Parchment canvas and serif labels. Teal is used for the question and evidence, crimson only for crux boxes, rust for Supporters and brown for Skeptics. Evidence carries the page's ＋/− glyphs. Dark mode was checked in screenshots.
- **Keyboard.** Each box is a focusable React Flow node with role `button`, an accessible name ("Crux 1 of 2, Safety Record: …") and a `ring-focus` ring. Tab follows reading order: question, then each crux with its supporters and their evidence, then its skeptics and their evidence. Enter, Space or a click opens the detail sheet. React Flow pans to a focused box that is off-screen.
- **Detail sheet** (`components/DiagramDetail.tsx`). It is a modal side sheet built on `useModalAccessibility`: focus moves into it, Escape or the backdrop closes it, and focus returns to the box.
  - **Contents.** Each part uses the page's labels:
    - Crux: "What would settle it" (the page's `SettleAnswer`), "A supporter / a skeptic changes their mind if…", the run-ins and "The test".
    - Side: the full case.
    - Evidence: "Supports the claim" or "Challenges the claim", the description, and the source link.
  - **Page link.** Each box links to the same place on the map page (`#crux-…` or `#positions`).
  - **Panning.** The canvas slides a box out from under the sheet when the sheet would cover it.
- **Chrome.** Only the zoom controls remain, now with focus rings. The hint was corrected: scroll pans rather than zooms.

**Phones** (`components/MobileArgumentList.tsx`):
- **Same tree, as an outline.** The outline is built from the same model and uses the same words: the question, then "This turns on three questions" (the page's heading helper), then each crux. Opening a crux shows What would settle it, Supporters and Skeptics (the first sentence, with the full case folded), their evidence (folded descriptions and sources), and a link to the crux on the map page.
- **Server-rendered.** The outline is rendered on the server with the route, so there is no "Loading the map…" state any more.
- **No lost taps.** The crux toggles stay disabled until the page hydrates, so an early tap isn't lost. This also keeps the existing e2e click reliable.

**Route** (`app/topics/[id]/map/page.tsx`):
- **Server-built.** The page loads the topic and builds the model on the server. The client no longer imports topic modules for this route.
- **Kept as before:** `noindex`, the canonical pointing at the map page, "Back to the map page", and 404 for flagship and unknown ids.

**Dead code deleted, with its tests:**
- **Store, blueprint and layout helpers:** `hooks/useLogicGraph.ts` (the expand/collapse store, including the Scales/Debate `ArgumentView`), `data/logicBlueprint.ts` (the placeholder nodes), `lib/layout.ts`, `lib/graphViewport.ts` and `lib/variantStyles.ts`.

- **Canvas components:** `MapLegend`, `NavigationPath`, `TopicIntroPanel`, `CruxModal`, `InteractiveContent`, `GlossaryTerm`, `ConfidenceBar` and `MiniGraphPreview`.
- **Helpers, types and constants:** the bracket-keyword helpers in `lib/utils.ts`, the unused `GRAPH` keys, `MINIMAP`, and the graph types except `Reference`.
- **CSS:** the canvas rules in `app/globals.css`.

## Left, and why

- **Five-crux maps open small.** On `scott-cost-disease`, `moloch`, `ai-2027` and `jones-act`, the whole tree opens at 51%, where side text is about 7.6px. The brief asks for the whole tree on load, so that is what these maps get; zoom and keyboard focus (which auto-pans) cover reading. Stacking the sides vertically would only reach about 57%, and two rows of cruxes would break the one-level tree, so I left the layout as it is. Four-crux maps open at about 64%. The tallest map, `consciousness-ai-systems` (seven cards under one side), opens at 57%.
- **`react-katex`, `katex` and `@types/katex` are now unused.** So is `types/react-katex.d.ts`. Removing them changes `bun.lock`, a shared file other agents install from, so it should be a one-line follow-up after the round merges.
- **CLAUDE.md is stale.** It still names `hooks/useLogicGraph.ts`, `nodes/RichNode…` and `data/logicBlueprint.ts`, and says the topic corpus is lazy-loaded in `useLogicGraph.ts`. The brief says never to edit it. Suggested lines:
  - `components/nodes/DiagramNode.tsx` — the diagram's one node type;
  - `lib/diagram/` — the diagram's model and layout, built from `lib/topicPage/legacy.ts`.
- **Stale comments in `data/glossaryTerms.ts` and `data/glossaryPageTerms.ts`.** They mention the deleted `<GlossaryTerm>` component. They are data files outside this task, so I left them.
- **Analytics.** Opening a box's detail fires the existing `node_expand` event, so the funnel keeps its "interacted with the map" signal. The `view_switch` type in `lib/analytics.ts` still lists `scales` and `debate`; it is analytics vocabulary rather than canvas code, so I left it.
