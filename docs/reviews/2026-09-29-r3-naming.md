## 1. One name per map

`lib/mapNaming.ts` → `mapDisplayTitle(map)` = `question` (trimmed), else `title`. Every place a map
is named to a reader now goes through it:

- topic page: H1, **breadcrumb** (now the question, truncated on one line by `Breadcrumbs singleLine`),
  "Keep exploring" related maps, JSON-LD headline, hero alt fallback
- ⌘K search results (`components/SearchModal.tsx`)
- paste: matched map, "Closely related", closest-map candidates (`lib/paste/mapDocuments.ts`,
  `lib/paste/maps.ts`), the copied summary
- diagram route: H1 and metadata (`lib/diagram/model.ts` now takes `page.title`)
- /questions index ("· map name" meta, search haystack) and question pages ("from the map …",
  related descriptions, next-map link)
- Learn: `mapLinkFor()` (feeds "Where it shows up", next-map links, the educators page)
- library + /saved (`app/topics/_query.ts`), dashboard, embed metadata
- topic-link tooltips in prose (`lib/topic-links.ts`), `feed.xml`, `llms.txt`, the OG card
- map-reply header and markdown (flag-off `/reply`)

### Where `title` is still used, and why
- **Matching, never display:** the search index (`altNames`), the paste index `name` field and the
  map-reply prefilter still index the old label so typing it finds the map;
  `lib/topic-links.ts` matches the short label as a phrase in running prose (its tooltip shows
  the question).
- **Metadata keywords** on the topic page (`keywords: [topic.title, …]`): not shown.
- **Public API** (`/api/v1/topics*`): `title` is a data field; left as the contract.
- **`/api/verdict-card`**: a retired verdict surface, untouched.
- Flagship `argumentTopicIndex.title` / `meta.title`: already questions.
- Pillar titles (crux kickers, rail labels) are pillar names, not map names.

## 3. Side labels that answer the question

Legacy sides are relative to `meta_claim`; each `question` is written so "yes" agrees with it. So,
for every map with a question (all 156):

| Where | Before | After |
|---|---|---|
| Position cards, diagram side nodes, phone outline | Supporters / Skeptics | **Says yes / Says no** |
| Mind-change lead-ins (topic crux fold, diagram detail, paste crux box, paste summary) | A supporter / A skeptic changes their mind if… | **Someone who says yes / no to the map's question would change their mind if…** |
| Paste evidence cards | Supports it / Cuts against it | **Points to yes / Points to no** + "Yes and no answer the map's question at the top, not the crux." |
| Topic-page crux evidence blocks | Supports / Challenges the claim | **Points to yes / no on the map's question** |

Why the long form under a crux: a crux question can be worded the other way round (nuclear crux 1:
"Do nuclear's rare-disaster and waste risks outweigh the fossil-fuel deaths it would displace?"
under "Should nuclear power be expanded…?"). A bare "Says yes" right under it would read as yes to
the crux: the same wrong-way confusion the review found. The short "Says yes" only stands where the
map's question is the nearest one (position cards; the diagram, whose intro now says "Yes and no are
answers to the question at the top"). Maps without a question keep Supporters / Skeptics
(`CLAIM_SIDES`); flagships keep their named camps. Some authored flip texts still open "A skeptic
focused on…": that is map data (`data/topics/*`, out of scope).

## 5. Search that finds the obvious

`lib/siteSearch.ts`: stop-words dropped ("is", "should", "the"…); fields `title` (question) ×4,
`altNames` (old title + "Also asked as" phrasings from `lib/questions.ts`) ×3, aliases ×2, claim /
tags ×1; then a rerank by how much of the query the result's *name* covers, ×2 for a phrase match,
×1.5 for a flagship only when its name covers every word. UI: titles wrap (no truncate), the
redundant "Map" pill is gone (the "Maps" group header says it), one neutral chip for every category.

Top result, before → after:

| Query | Before | After |
|---|---|---|
| is nuclear power safe | nuclear-weapons-abolition | **nuclear-energy-safety** |
| nuclear energy safe | (not measured) | nuclear-energy-safety |

| climate change human caused | climate-change | climate-change |
| UBI | universal-basic-income | universal-basic-income |
| universal basic income | universal-basic-income | universal-basic-income |
