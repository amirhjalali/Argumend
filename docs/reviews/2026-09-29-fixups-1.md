### 1. Diagram blank on phones
- **Cause:** `setTopic()` sets the id before the topic module arrives. The module cache is not reactive, so `MobileArgumentList` read nothing and never re-rendered.
- **Fix:** the store now records `loadedTopicId` when a topic's graph is applied. `useLoadedTopic()` (`hooks/useLogicGraph.ts`) re-renders on it. While it waits, the outline shows "Loading the map…" instead of nothing.
- **Repro:** I delayed the topic chunk by 2.5s with Playwright. Before the fix, `/topics/climate-change/map` at 390px stayed empty (`innerHTML ""` after 12s). After the fix, the outline renders once the chunk lands.
- **Verified** on six maps at 390 and 1440: climate-change, pfas-forever-chemicals, nuclear-energy-safety, universal-basic-income, moon-landing, minimum-wage-effects. Screenshots: `item1-final-<id>-<width>.png` and `item1-final-pfas-390-pillar-open.png`.
- **Test:** `app/topics/[id]/map/TopicDiagram.test.tsx` renders the phone diagram with the topic load held back. It fails against the old outline.
- **Copy:**
  - "Evidence (N for, M against)" is now "Evidence on each side".
  - "Decisive Test:" is now "What would settle it:".
  - "N Key Arguments" is now "N key arguments".

### 2. Modal scroll lock
`lockPageScroll()` (`hooks/useModalAccessibility.ts`) locks both `<html>` and `<body>`.
- Where a classic scrollbar takes up space, it keeps the scrollbar gutter so the layout does not jump.
- Each lock restores the inline values it found, so nested dialogs unwind in order.

Measured in Chromium:

| Dialog | Viewport | Scroll input | Before | After |
|---|---|---|---|---|
| Phone menu on /about | 390px | wheel, then touch | 0 → 800 → 1407 | 0 |
| Search | 1440px | wheel | 59 → 959 | no change |
| Embed on a topic page | 390px | touch | 2454 → 3061 | no change |

Unit test: html and body lock, and nested unwind. The source contract now forbids any other `.style.overflow =` in `app/` and `components/`.

### 4. Old "Map" links
The `/?topic=` rule moved from `next.config.js` to `proxy.ts` (`legacyHomeTopicPath` in `lib/dynamicRoutePolicy.ts`), because `redirects()` cannot drop the incoming query. It is one 308 with no chain:

| Incoming link | Destination |
|---|---|
| `view=graph` or `view=logic-map` on a legacy map | `/topics/X/map` |
| Any other view, or a new-model map (no diagram) | `/topics/X` |
| Empty or unknown id | `/topics` |

- `topic` and `view` are dropped. Other parameters such as `utm_*` and `ref` are kept.
- The proxy matcher only admits `/` when `?topic=` is present.
- **Behaviour change:** an unknown id used to 404 at `/topics/<id>`. It now lands on the library.
- The `view=read` pin is gone. The loop it guarded no longer exists, because `/topics/X?view=graph` goes to `/map` and never back to `/?topic=`. This was checked with curl.
- `next.config.test.ts` now asserts that there is no `/` rule. The proxy cases live in `lib/dynamicRoutePolicy.test.ts`.
