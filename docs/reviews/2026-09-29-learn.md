# Learn library, 2026-09-29

Branch `ux/learn`, cut from `ux/site-overhaul-2026-09-29` and merged up to its
tip three times (topic template, home + story, paste flow, maps library). Spec:
`docs/reviews/2026-09-29-site-review/4-content.md` (F1–F14 and "Proposed
learn/content structure"), with the overhaul brief's decisions.

The library was eight mini-sites and two search layers with five hero styles
and three body typographies. It is now one hub (`/learn`), one article
template and one index template, and every article ends on a map and the
paste tool.

## What changed

**Two templates** (`components/learn/`):

- `ArticleLayout`: crumbs Home › Learn › Section › Title, an eyebrow naming
  the kind (Essay, Guide, Idea, Fallacy, Question), the regular-weight serif
  title from `PageHeader`, a one-sentence lede, a meta line, a serif body in
  the 44rem reading column, a contents list only when a page has more than
  four H2s, optional key takeaways. It ends with exactly two blocks: **Next
  step** (one map, then "Try it on an argument you're in" → `ANALYZE_HREF`)
  and up to three related pages. No newsletter, catalogue numbers, icon
  circles, category colours or share row.
- `CollectionIndex`: the same header, at most six neutral chips (the current
  one teal), groups of compact hairline rows (title, one line, a muted meta
  line, `min-h-11`), thumbnails only where a page passes them (the blog).
- `lib/learn/`: the shared vocabulary (`sections.ts`), the next-step map
  picker (`nextStep.ts`: the page's own map, else a map its text links, else
  the flagship that fits its words), read time and month helpers, the
  glossary model, and the `/is` redirect table.

## Redirects (permanent, `next.config.js`, the "learn" block)

|---|---|
| `/concepts` | `/learn#ideas` |
| `/guides` (index only) | `/learn#guides` |
| `/library` | `/research#reading` |
| `/lessons-from-the-deep` | `/blog` |
| `/is` | `/questions` |
| `/is/:slug` (140) | `/questions/<primary slug of the same map>`, from `lib/learn/isToQuestions.json` |

Before the redirects, the 58 maps that had an `/is` page but no question page
got that `/is` question as their primary phrasing in `lib/questions.ts`, so
every `/is` URL lands on a real page. `lib/learn/isToQuestions.test.ts` fails
if any entry stops pointing at an existing primary question for the same map.
Checked on the dev server: each redirect returns 308 and keeps the `#anchor`.
Secondary `/questions` phrasings are **not** redirected.
