# Argumend 1.0 — Execution Plan (Orchestration)

> **For agentic workers:** This is the program-level orchestration plan for
> `docs/plans/2026-08-09-argumend-1.0-disagreement-engine.md`. Each package gets its own
> bite-sized implementation plan (superpowers:writing-plans format) authored by Fable at
> dispatch time; execute those with superpowers:subagent-driven-development or the Codex
> worktree harness as routed below.

**Goal:** Ship Argumend 1.0 (prune → ontology → crux engine → flagship nuclear topic → mobile-first UX → evidence system) at minimum Claude-quota cost, with Fable as sole architect, reviewer, gatekeeper, and merger.

**Architecture:** Work is routed by the codex-delegation quota weights (Fable 10 / Opus 5 / Sonnet 3 / Haiku 1 / Codex 0). Codex does recon, research, and typing in isolated worktrees; Sonnet subagents draft where Claude-quality drafting matters; Opus provides diverse adversarial review; Fable writes every brief, reads every diff, runs every gate, and makes every merge and judgment call. Waves are ordered so cheap lanes are always saturated while Fable-only work (ontology decisions, reviews) happens in parallel.

**Tech stack:** Existing repo stack (Next.js 16, React 19, TS strict, Bun, React Flow, Drizzle, Vitest). No new infrastructure.

## Amendments (2026-08-10, post-Wave-1)

- **Flagship topic switched: nuclear → AI and jobs.** Founder's call after the baseline link-drop got muted responses and Wave 1's own research documented nuclear's depolarization (Gallup 61% favor, bipartisan support). Working question: *"Will AI cause mass unemployment in the U.S. within the next 15 years?"* (phrasing adjustable). Criteria: tribal heat + live expert disagreement + mixed empirical/predictive/normative cruxes + matches likely early audience. The nuclear corpus (`docs/research/2026-08-10-nuclear-flagship/`) is retained as the second-wave deep topic; the research→adversarial→verification pipeline it validated is reused as-is.
- **Second target after the flagship proves out:** America's support for Israel / the Iran strikes (founder's pick for maximum heat). Conditions before starting it: flagship must have demonstrated fairness credibility first; adversarial QA must include reviewers prompted from both communities' perspectives; prefer entering via the narrower Iran-strikes question (empirically anchored) before the broader Israel-support question.
- Baseline north-star result recorded in `docs/research/2026-08-10-north-star-baseline.md`: **muted**. Wave 4's test #2 should send both the new flagship and the nuclear topic in the new UX to separate topic-heat from UX effects.

## Global Constraints

- **Merge gates, run by Fable, unmasked exit codes** (never `&&`-chained when reading `$?`): `bun run typecheck` · `bun run lint` (`--max-warnings=0`) · `bun test` · `bun run build`. Evidence/citation work additionally gates on `bun run check:sources`.
- **Codex reads no CLAUDE.md.** Every brief inlines the repo hard rules: `getDb()` lazy init (never import `db`); feature flags default off/offline; `@/*` path alias; Bun scripts; design tokens (no amber/tangerine; rust `#C4613C`, teal `#3a6965`, crux crimson `#a23b3b`); dark mode via CSS vars; `*.test.ts` excluded from Tailwind content scan.
- **Codex model:** pass `-m gpt-5.5` explicitly (incumbent beat 5.6-sol in audition). `model_reasoning_effort=medium` for mechanical work, default xhigh for recon/research.
- **Worktrees branch from origin/main** — push local commits before dispatching, or referenced files are invisible. Inline samples of any JSON/data file a brief references; never just the path.
- **Review is never delegated.** Fable reads full diffs, verifies literal constants at file:line, greps all call sites when an exported signature changes, distrusts negative claims ("X doesn't exist") until actively probed.
- **Mobile-first mandate:** all UX packages are designed and reviewed at 390px first; north-star tests run on a phone.
- **Founder checkpoints** (the only non-agent steps): approve the pruning classifications before implementation; run the baseline north-star link-drops; approve the ontology spec; approve each wave's merge to main.

## Wave 1 — Audits, research, baseline (all lanes parallel; near-zero Claude draw)

Everything in this wave is read-only or founder-action. No merge conflicts possible; dispatch all four concurrently.

### W1.1 — Package B recon: Product pruning audit — **Lane: Codex (read-only)**

One `codex exec -C <repo> -s read-only -m gpt-5.5` pass over `app/` routes, nav components (`TopBar`, `Sidebar`, `Footer`, `AppShell`), and feature flags. Brief inlines the CORE / KEEP-HIDE / MERGE-DEPRECATE taxonomy and the plan's CORE list verbatim, plus: per route report inbound links, nav placement, mobile behavior at 390px, test coverage, and a recommended classification with reasoning. Output: draft `docs/PRODUCT_PRUNING_AUDIT.md`.

**Fable validation:** spot-check 5 random route classifications against actual source; verify every `app/` top-level dir appears in the table (count check, no silent omissions). **Founder checkpoint:** approve/amend classifications.

### W1.2 — Package A recon: Architecture audit — **Lane: Codex (read-only)**

Second parallel read-only pass over `types/graph.ts`, `types/logic.ts`, `types/debate.ts`, `lib/schemas/`, `lib/db/schema.ts`, `data/topics/` (inline one full sample topic file in the brief), `lib/analyze/`, `lib/judge/`, `lib/debate/` output shapes. Deliverable: current-state data-model map — every node/edge concept that exists today, where it's defined, where the same concept is defined twice, and a gap table against the plan's 14 node types / 9 edge types. Output: `docs/audits/2026-08-argument-model-current-state.md`.

**Fable validation:** verify the file:line refs for the 5 most load-bearing claims; literal constants are Codex's weak spot.

### W1.3 — Package F start: Flagship nuclear research — **Lane: Codex (web research)**

3–4 parallel `codex exec -s read-only --ephemeral -c tools.web_search=true -m gpt-5.5` runs, one per sub-question: (a) economics of new nuclear construction (Vogtle, SMRs, learning rates); (b) renewables+storage reliability equivalence; (c) risk valuation frameworks (LNT, comparative mortality); (d) waste/proliferation/regulatory. Briefs demand: primary sources (EIA, NRC, IPCC, Lazard LCOE, NREL, peer-reviewed), per-claim citation with URL, explicit UNVERIFIED flags, and the strongest credible version of each side. Seed name/term variants explicitly. Output: cited reports in `docs/research/2026-08-10-nuclear-flagship/`.

**Fable validation (cheap, non-LLM first):** `curl -sIL` liveness on every cited URL; probe permutations for any negative claim; then read for balance. **Opus (one subagent):** adversarial balance pass over the merged corpus — "argue this research unfairly favors each of: expansion / anti-nuclear / renewables-first."

### W1.4 — Baseline north-star test — **Lane: Founder (the irreducible atom)**

Send the current nuclear topic URL to 3–5 people, on their phones, with one question: "5 minutes — did this help you understand the debate better than asking ChatGPT would?" Record verbatim reactions in `docs/research/2026-08-10-north-star-baseline.md`. This is the control group for every later wave.

## Wave 2 — Prune + ontology (gated on W1)

### W2.1 — Package B implementation: low-risk pruning — **Lane: Codex (worktree)**

After founder approves classifications: `codex-task.sh start codex/prune <brief>` implementing only HIDDEN and low-risk MERGE items — nav reduction toward Explore · Analyze · About, route de-linking (not deletion), flag-gating dormant features. Brief lists exact files, exact nav target, "Do NOT touch" list (auth internals, DB schema, topic data), and requires updating affected tests. DEPRECATE/REMOVE items wait for a later founder pass.

**Fable:** full diff review (check adds-vs-swaps, prettier-reflow hunks), run all four gates unmasked, merge. This is the first visible product change; keep it revertable as one squash commit.

### W2.2 — Phase 1 ontology spec — **Lane: Fable (judgment; not delegable), timeboxed**

Fable writes `docs/ARGUMENT_MODEL.md` from W1.2's gap table + W1.3's real material — content decides which distinctions earn a type. **Timebox: 2 working sessions.** Bias: fewer types; every type must be exercised by the flagship topic or it's cut. Includes valid/invalid example graphs and AI-extraction guidelines per the plan.

**Opus (one subagent):** adversarial spec review — attack ambiguity between types, undercut-vs-rebut confusion, unrepresentable real arguments (use W1.3 material as test cases). **Founder checkpoint:** approve spec.

### W2.3 — Package C: ontology implementation — **Lane: Codex (worktree), plan by Fable**

Fable writes a full writing-plans-format implementation plan (bite-sized TDD tasks, actual code in steps) for: TS types in `types/argument.ts`, Zod runtime schemas in `lib/schemas/argument.ts`, validators + fixture tests, and a conversion adapter from the current topic format (exercised against the inlined sample topic from W1.2). Backwards compatible — existing 109 topics keep rendering. Codex executes in a worktree.

**Fable:** diff review with special attention to weak/tautological tests; gates; merge.

## Wave 3 — Crux engine + flagship assembly (parallel)

### W3.1 — Package D: crux algorithm research — **Lane: Codex ×2 + Sonnet ×1, judged by Fable**

Three independent proposals for crux scoring over the W2.3 graph model: two Codex runs (one graph-theoretic: centrality/dependency/counterfactual reach; one hybrid LLM+structure) and one Sonnet subagent (grounded in the actual flagship graph shape). Each must include: scoring function, worked example on a 20-node toy graph, failure modes. Fable writes the decision doc `docs/CRUX_ENGINE.md` — synthesis is weight-10 work; the proposals are not.

### W3.2 — Package F assembly: flagship topic graph — **Lane: Sonnet draft → Codex encode → Opus adversarial → Fable judge**

Sonnet subagent drafts the argument graph (positions, claims, premises, objections, rebuttals, assumptions, epistemic tags) from W1.3's verified research, in the W2.2 ontology. Codex encodes it into the `data/topics/` format with full citations. Opus panel (2 subagents) runs the plan's fairness attack. Fable arbitrates disputes and owns final content judgment — this graph IS the product thesis.

**Gates:** schema validation tests + `bun run check:sources` on every citation.

### W3.3 — Package E: crux engine implementation — **Lane: Codex (worktree), plan by Fable**

From the W3.1 decision doc: deterministic scoring in `lib/crux/`, test fixtures from the flagship graph, explanation generation. Same review/gate discipline as W2.3.

## Budget & discipline notes

- Fable spend concentrates in: briefs, the ontology spec, crux decision doc, flagship arbitration, Layer 1–2 design, and every review — nothing else. Anything mechanical that lands on Fable's desk gets re-routed down a lane.
- Batch Codex questions; per-exec overhead is ~10k tokens. Never dispatch one-liners.
- Serialize worktree creation, parallelize the execs. Keep `-o` outputs outside worktrees.
- Escalate without asking when a cheap lane's output misses the bar — one rung up, redo.
- After each wave: append surprises to the codex-delegation skill's lessons; update memory with wave status.
